## 1. 찾아서 고친 것

### 🔴 A. `known_modes` 기본값이 빈 리스트 → 매니저가 시작하자마자 죽음

팀원이 먼저 발견. **내 코드 버그였다.**

```python
self.declare_parameter("known_modes", [])
```

rclpy 는 기본값의 **원소**를 보고 타입을 정한다. 빈 리스트는 원소가 없다.

```
[]                     → BYTE_ARRAY     (원소가 없어 바이트 배열로 잡힘)
["IDLE","START", …]    → STRING_ARRAY   (yaml 이 주는 것)
```

선언 타입과 yaml 타입이 달라 죽는다.

**고침**: 기본값을 `[""]` 로. 원소가 문자열이라 STRING_ARRAY 로 확정된다.
읽을 때 빈 문자열을 버리므로 실질 기본값은 "비어 있음" 그대로다.
**모드 목록은 yaml 한 곳에만 둔다** — 코드에도 박으면 구간 이름이 바뀔 때
yaml 만 고친 사람과 어긋난다.

목록이 비면 이제 크게 경고한다 (params-file 빠뜨림 감지).

### 🔴 B. `/mcu/ready` 를 두 노드가 발행

```
브릿지 pub_topic_ready      = "/mcu/ready"   아두이노 통신이 살아있나
매니저 status_ready_topic   = "/mcu/ready"   중재기가 명령을 내보내나
```

타입도 Bool 로 같아서 **에러가 안 난다.** 구독자만 깜빡이는 값을 본다.

**고침**: 매니저 쪽을 `/mcu/manager_ready` 로.

### 🔴 C. `package.xml` 에 `rcl_interfaces` 누락

오늘 `ParameterDescriptor` 를 쓰면서 생겼다.
내 PC 엔 이미 깔려 있어 돌지만, 팀원이 `rosdep install` 로 환경을 만들면 빠진다.
**전형적인 "나는 되는데" 버그.**

### 🔴 D. `/odom` 과 TF 를 두 곳이 발행 (오늘 낮에 처리)

```
브릿지            /odom  + TF odom→base_link
wheel_odom 노드   /odom  + TF odom→base_footprint
```

**고침**: 브릿지를 `/mcu/odom` 으로 옮기고 `publish_tf: false`.
IMU yaw 를 쓰는 wheel_odom 이 주인이 맞다.

⚠ 대신 `base_footprint → base_link` 를 누가 쏘는지 확인해야 한다.

### 🔴 E. 워치독이 홀딩을 방해 (펌웨어)

`updateDriveWatchdog` 가 `H` 홀딩 중에도 돌아서, 2초 뒤 목표 PWM 을 0 으로
떨구고 `updateHold` 와 매 루프 싸우고 있었다. 홀딩·안티롤백 중에는 건너뛴다.

## 3. 앞으로 자동으로 막는 장치

### `tools/audit.py` — 정적 감사 (ROS 불필요)

소스와 yaml 의 아귀를 11가지로 본다. **`설치.sh` 가 빌드 직후 자동 실행한다.**

```
[1]  yaml 섹션 == 노드 이름          섹션이 통째로 무시되는 것을 막는다
[2]  파라미터 타입 불일치            ← A 를 잡는 검사
[3]  yaml 에만 있는 키               오타가 조용히 무시되는 것을 막는다
[4]  빈 컨테이너 기본값
[5]  토픽 이중 발행                  ← B 를 잡는 검사
[6]  매니저 출력 ↔ 브릿지 입력
[7]  포트·홈경로·IP 하드코딩
[8]  package.xml 의존성 ↔ 실제 import  ← C 를 잡는 검사
[9]  setup.py entry_points / data_files
[10] launch 이름
[11] 파이썬 문법
```

### `tools/preflight.py` — 각자 자기 PC 점검 (실행 환경)

정적 감사가 못 보는 것. **각자 자기 PC 에서 돌린다.**

| 검사 | 안 맞으면 |
|---|---|
| `ROS_DOMAIN_ID` / RMW | 노드끼리 **아예 안 보인다** |
| `dialout` 그룹 | 포트 열 때 permission denied |
| 포트를 누가 잡고 있나 | 브릿지 두 개가 서로 뺏는다 |
| **`install/` 이 `src/` 보다 오래됐나** | ★ 소스를 고쳐도 옛날 코드가 돈다 |
| `t870_mcu` 중복 설치 | 어느 것이 도는지 모른다 |
| 노드 이름 중복 | 같은 노드를 두 번 띄움 |
| 한 토픽에 발행자 2개 이상 | 값이 번갈아 들어와 튄다 |
| Cyclone + Docker veth | 같은 PC 안에서도 못 찾는다 |

### `diagnostics.py` — 실행 중 타입·QoS 불일치 감지

ROS 에서 메시지가 안 오는 이유는 셋인데 **셋 다 에러가 안 난다.**

1. 아무도 발행 안 함 → 상대 노드가 안 떠 있음
2. **메시지 타입이 다름** → Float32 로 쏘는데 Int32 로 구독
3. **QoS 가 다름** → BEST_EFFORT 발행 vs RELIABLE 구독

2·3 번은 토픽 이름이 똑같아 `ros2 topic list` 로는 정상으로 보인다.
`ros2 topic echo` 로는 보이는데 노드만 못 받는 상황이 이것이다.
**팀마다 PC 가 달라 정확히 "나는 되는데 너는 안 된다" 로 나타난다.**

브릿지·매니저가 3초마다 확인해 처음 한 번만 크게 찍는다:

```
[ERROR] camera 구동: '/camera_drive' 메시지 타입이 다르다 —
        /camera_node 는 std_msgs/msg/Int32 로 쏘는데
        우리는 std_msgs/msg/Float32 로 구독한다. 이러면 한 개도 안 들어온다.
```

발행자가 아직 없는 것은 정상이라 조용히 넘어간다 (소음 방지).
